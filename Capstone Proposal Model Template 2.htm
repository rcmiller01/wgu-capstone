Capstone Project Name: A Paired t-Test Analysis of a Serverless FHIR Lakehouse for Streamlined and Consistent Rural Health Data Exchange

 

Project Topic: Serverless FHIR Data Pipeline for Rural Healthcare Interoperability

 

☒ This project does not involve human subjects research and is exempt from WGU IRB review.

 

 

Research Question: How can implementing a cloud-based, serverless FHIR-compliant data pipeline streamline health-data exchange, reduce operational friction, and raise data consistency across a distributed rural healthcare network while maintaining compliance and scalability?

 

Hypothesis: H0: Implementation of the serverless FHIR pipeline will produce no statistically significant change in data consistency or timeliness compared with the current manual process.

                             

                   H1: Implementation of the serverless FHIR pipeline will produce a statistically significant improvement in data consistency and timeliness as measured by a paired t-test (p < .05).

 

Context: This study examines whether a serverless, FHIR-compliant data pipeline can make rural health-network data sharing more consistent, timely, and frictionless. Many small hospitals and clinics operate with fragmented systems and delayed data flow. By automating ingestion and validation within a lightweight serverless design, the project aims to demonstrate measurable improvement in how reliably information moves across the network. The focus is on the efficiency and quality of data movement rather than patient outcomes, aligning with the MSDA program’s emphasis on applied analytics and measurable operational results.

 

Data: The data used to answer the research question will be collected from publicly available and synthetic healthcare sources that mirror the variety of data formats used in rural settings—structured (EHR tables, surveys), semi-structured (HL7 and JSON health messages), and unstructured (radiology images). These types of datasets are frequently used in applied analytics research because they are large, heterogeneous, and statistically suitable for modeling performance and data-quality improvement (Evans, 2020; Santos & Costa, 2020).

The combined dataset, before transformation or cleaning, contains approximately 7,000 structured records and 1,000 radiology images. These datasets are maintained by recognized health organizations and synthetic generators, ensuring strong data integrity and full HIPAA compliance through de-identification (Statistics with R, WGU, 2023).  Limitations: Because the study uses public and synthetic data, baseline ingestion performance must be inferred rather than measured directly. Estimates are drawn from time-motion and abstraction studies reporting 15 to 45 minutes per record for manual entry and validation (Mehmood et al., 2013; Overhage et al., 2020; Jabour et al., 2018; UCSF Healthforce, 2024). This introduces some uncertainty into the paired-sample comparison but provides a realistic operational frame for rural settings.  Delimitations: The study focuses on data engineering performance and accuracy, not clinical impact or outcomes.

 

Data Gathering: The Treatment of the Data: Each dataset will be downloaded in CSV, JSON, or image format and loaded into a serverless cloud data lake. Records missing key identifiers such as patient_id or encounter_date will be removed or imputed (mean for numeric fields, mode for categorical). Addressing missing data at this stage prevents distortion in the statistical tests (Swalin, 2018). Python will be used to clean, merge, and transform the data. Outliers beyond 1.5 × IQR will be winsorized or flagged for review. Derived variables—latency_sec and validation_pass_bool—will capture the two key measures for testing. Great Expectations (2024) will automate validation and schema enforcement, providing audit trails of successful and failed ingestions. Because there is no live production feed, paired samples will be created by processing identical inputs through two paths: a modeled manual path reflecting the 20-minute, 85 percent baseline performance, and the automated path using the serverless FHIR pipeline. This approach provides a direct before-and-after comparison for the paired t-test and Wilcoxon follow-up if the data are non-normal.

 

Data Analytics Tools and Techniques: The Design of the Study: A Q-Q Plot and Shapiro-Wilk test will be used to check normality (Evans, 2020). If the distribution is normal, a paired-samples t-test will be run to compare baseline and post-pipeline performance. If normality is violated, a Wilcoxon Signed-Rank test will be used as the non-parametric alternative (WGU, 2023). Cohen’s d will quantify the magnitude of improvement at the α = .05 significance level. Python (Pandas, SciPy, and Great Expectations) will handle data analysis and validation. Power BI dashboards will visualize data flow and quality patterns across Virginia health districts.

 

Justification of Tools/Techniques: Python provides scalable and reproducible analytics and integrates well with AWS and Azure serverless environments (Evans, 2020). According to Data Science Using Python and R (WGU, 2023), Python’s libraries allow efficient statistical testing within modern data architectures. Its combination of flexibility and industry adoption makes it a practical choice for a study focused on data integration and workflow improvement.).

 

Project Outcomes: The project will determine whether a serverless FHIR pipeline can make health data exchange more consistent, timely, and scalable for rural networks. Support for the alternative hypothesis will be shown if the paired t-test produces a p-value less than .05. A confirmed improvement would demonstrate that the proposed architecture reduces bottlenecks in data movement and raises overall record accuracy and trust levels for health system decision makers (Santos & Costa, 2020).
